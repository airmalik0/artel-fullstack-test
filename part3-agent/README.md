# Claude Code на моделях DeepSeek и развёртывание VPN-узла

Папка агента. Одна команда поднимает Claude Code, который вместо моделей Anthropic работает на
DeepSeek. Команда `/deploy-server <host>` ведёт пайплайн: с чистого сервера до рабочего выходного
узла VPN с тремя транспортами: Xray VLESS+Reality на TCP/443 основным, второй inbound Reality на
TCP/8443, Hysteria2 с обфускацией Salamander на UDP/443 запасным. Те же транспорты названы в
топологии из части 2. Удалённый доступ к живой сессии через tmux, отдельный ключ только на просмотр.

Детерминированную работу делают скрипты, агент выбирает шаг, читает JSON результата и разбирает
сбои. Успех определяет `scripts/verdict.sh`, а не текст модели. Всё ниже я прогнал на двух свежих
дроплетах DigitalOcean: хост агента и чистая цель. Выдержки логов лежат в `evidence/`.

## Что где лежит

```
start.sh                запуск Claude Code на DeepSeek
deploy.sh               развёртывание без человека, код возврата из verdict.json
build-archive.sh        сборка архива без секретов
CLAUDE.md               правила агента
.env.example            шаблон настроек
.claude/settings.json   env, разрешения, песочница, хуки
.claude/commands/       /deploy-server
.claude/agents/         recon, deployer, verifier, troubleshooter
.claude/hooks/          guard.py (запреты), verdict_gate.py (нельзя закончить без проверки)
scripts/                шаги развёртывания, verdict, диагностика
scripts/remote/         то, что выполняется на цели
tools/                  установка хоста, ключи, tmux, намеренные сбои, проба обхода, wire-tap
evidence/               выдержки логов живых прогонов, без секретов и адресов
```

## Как повторить за 10 минут

Нужны токен DeepSeek и два сервера Ubuntu 24.04 с входом под root: хост агента (я брал 2 ГБ) и чистая
цель (1 ГБ). Цель будет перенастроена, root на ней закроется.

1. Хост агента. Установка занимает около минуты:

```
scp artel-agent.tar.gz root@<хост-агента>:/root/
ssh root@<хост-агента>
tar -xzf artel-agent.tar.gz
part3-agent/tools/bootstrap-agent-host.sh
mv part3-agent /home/agent/ && chown -R agent:agent /home/agent/part3-agent
sudo -iu agent
```

2. Настройка под пользователем `agent`:

```
cd ~/part3-agent
cp .env.example .env          # вписать DEEPSEEK_API_KEY
./start.sh -p "Сколько будет 2+2? Ответь числом."
tools/new-target-key.sh       # печатает публичный ключ
```

3. Напечатанный ключ дописать на цели в `/root/.ssh/authorized_keys`.

4. Развёртывание. Интерактивно: `./start.sh`, внутри `/deploy-server <ip-цели>`. Без человека, около
трёх минут:

```
./deploy.sh <ip-цели>; echo "код возврата $?"
jq '{ok, changed_this_run, checks}' output/<ip-цели>/verdict.json
```

В `checks` должны быть `transport_reality`, `transport_reality_alt` и `transport_hysteria` со статусом
`ok` и `exit_ip`, равным адресу цели: настоящие клиенты Xray и Hysteria с хоста агента вышли в интернет
через узел каждым транспортом. Второй запуск `./deploy.sh` даёт `changed_this_run: 0`. Клиентские
конфиги появятся в `output/<ip-цели>/client/`: `xray-client.json` с двумя outbound и локальными SOCKS
10808 и 10810, `hysteria-client.yaml`, `links.txt`. Это секреты, в git и архив они не идут, агенту не
показываются. Порт второго Reality и имена `serverNames` задаются в `.env`: `REALITY_ALT_PORT`,
`REALITY_SNI`, `REALITY_EXTRA_NAMES`. Новое имя меняется в конфиге клиента, узел переустанавливать не надо,
если оно уже в списке. Каждое имя должен отдавать тот же сайт с верным сертификатом, шаг `recon` это проверяет.

5. Доступ к живой сессии. На своей машине в распакованной папке:

```
mkdir -p secrets
ssh-keygen -q -t ed25519 -N '' -f secrets/operator_ed25519
ssh-keygen -q -t ed25519 -N '' -f secrets/viewer_ed25519
scp secrets/*.pub root@<хост-агента>:/tmp/
ssh root@<хост-агента> /home/agent/part3-agent/tools/tmux-access-setup.sh /tmp/operator_ed25519.pub /tmp/viewer_ed25519.pub
tools/attach.sh agent@<хост-агента>       # оператор, сессия поднимется сама
tools/attach.sh agent@<хост-агента> ro    # только просмотр
```

Отключиться, не трогая сессию: `Ctrl-b`, затем `d`.

6. Две проверки из моего отчёта. Первая тратит копейки, вторая токен не тратит:

```
ssh root@<хост-агента> 'cd /home/agent/part3-agent && tools/check-isolation.sh /tmp/iso.txt'
tools/guard-probes.sh default     # на хосте под agent, ещё режимы wide и sandbox
```

## Какие настройки реально работают

Подбирал по документации DeepSeek и Claude Code, потом проверял прогоном: смотрел запрос на проводе
через `tools/wire-tap.py` и SNI соединений через tcpdump. Сырьё в `evidence/07-settings-matrix.txt` и
`evidence/10-model-routing.txt`.

| Настройка | Значение | Что показал прогон |
|---|---|---|
| `ANTHROPIC_BASE_URL` | `https://api.deepseek.com/anthropic` | обязательна, путь `/v1/messages` Claude Code добавляет сам |
| `apiKeyHelper` | чтение файла с токеном | работает вместо `ANTHROPIC_AUTH_TOKEN`, `/status` показывает его как источник ключа, токена нет в окружении claude и его подпроцессов |
| `ANTHROPIC_MODEL` | `deepseek-flash[1m]` | обязательна: без неё уходит `claude-opus-5-5`. DeepSeek принимает это имя и отвечает без ошибки, а какая модель отвечает на самом деле, по ответу не видно. Суффикс `[1m]` на провод не идёт, только задаёт окно контекста |
| `ANTHROPIC_DEFAULT_OPUS_MODEL` | `deepseek-v4-pro[1m]` | `model: opus` у подагента troubleshooter даёт v4-pro |
| `ANTHROPIC_DEFAULT_SONNET_MODEL` | `deepseek-flash[1m]` | `--model sonnet` и `model: sonnet` у подагента берут модель отсюда: с v4-pro в этой переменной на проводе v4-pro |
| `ANTHROPIC_DEFAULT_HAIKU_MODEL` | `deepseek-flash` | `model: haiku` у подагента и фоновый вызов. WebFetch обрабатывает страницу отдельным запросом, и он идёт в модель из этой переменной |
| `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` | `1` | главная: без неё два соединения с `api.anthropic.com` за запуск, с ней ни одного. `DISABLE_TELEMETRY`, `DISABLE_ERROR_REPORTING` и `DISABLE_AUTOUPDATER` вместе оставляют одно, поэтому их убрал |
| `skipWebFetchPreflight` | `true` | без неё WebFetch ходит на `api.anthropic.com` даже при отключённом трафике |
| `CLAUDE_CODE_ATTRIBUTION_HEADER` | `0` | убирает из системного промпта блок с версией и отпечатком клиента, промпт короче на 104 символа |
| `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS` | `1` | без неё в интерактивной сессии подагенты уходили в фон, модель сама ставила цикл ожидания и упиралась в окно подтверждения. С ней окон за весь `/deploy-server` ноль |
| `API_TIMEOUT_MS` | `600000` | не подтверждено. Запас на долгие ответы. На молчащем сервере первый прогон оборвал запрос за 4,2 с при значении 3000, два повторных с 3000 и 9000 не оборвали за 40 с. Причину не разбирал |
| `CLAUDE_BASH_MAINTAIN_PROJECT_WORKING_DIR` | `1` | при `1` следующая команда снова в корне, при `0` остаётся в подкаталоге. В поставке `cd` и так отклоняет `blockReadsOutsideWorkingDirectories`, переменная страхует |

Проверил и не использую:

| Настройка | Что показал прогон |
|---|---|
| `ANTHROPIC_SMALL_FAST_MODEL` | действует на тот же фоновый вызов, что и `ANTHROPIC_DEFAULT_HAIKU_MODEL`. Второй переменной не нужно |
| `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` | на Linux сажает в песочницу все команды: разрешённый шаг `recon` падает с «нет ключа для входа на цель». Вместо неё токен вынесен в `apiKeyHelper` |
| `CLAUDE_CODE_EFFORT_LEVEL` | действует, доходит до `output_config.effort`. Оставил умолчание `high` |
| `MAX_THINKING_TOKENS=0`, `CLAUDE_CODE_DISABLE_THINKING=1` | действуют, `thinking` исчезает из запроса. Не нужны |
| `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` | не нужна: DeepSeek принимает все заголовки beta, ответ 200. С ней инструментов в запросе 21 вместо 12 |
| `CLAUDE_CODE_SUBAGENT_MODEL` | действует, но перекрыла бы роли подагентов |

Подставная модель нужна потому, что настоящая сама отказывается читать секреты, и защиты остаются
непроверенными. Первый зелёный результат этих проб был ложным: bwrap падал на старте. Этот случай
исправлен, в отчёт взяты только прогоны, где команды внутри песочницы реально выполнялись.

Пробой на подставной модели нашлись и закрыты: подложенный `json.py` в корне папки выполнялся вне
песочницы, файл `CLAUDE.local.md` и кэш бинарников писались из песочницы.

## Что отличается от работы с Anthropic

- `total_cost_usd` и `/cost` считают по ценам Anthropic: один прогон развёртывания показывает 0,35, а баланс
  DeepSeek за три запуска подряд снизился на 0,03. Смотреть надо на баланс DeepSeek.
- В stderr на каждый запуск идёт предупреждение `unrecognized_model`. На работу не влияет.
- PDF не уходит document-блоком: Read вернул сырой файл, маркер модель достала, но за 6 ходов.
- `cache_control` DeepSeek игнорирует, кэширует сам: `cache read` приходит, запись в кэш всегда 0.
- Обычная сессия из одного вопроса фоновых вызовов не делает, поэтому сравнивал по WebFetch.
- `/status` пишет, что глобы в правилах песочницы на Linux поддержаны не полностью. Поэтому секреты
  в песочнице закрыты явными путями, а не масками.

## Ограничения

- Прогоны только на Ubuntu 24.04 amd64 в одном дата-центре. Ubuntu 22.04, Debian 12 и 13, arm64 не
  проверено, хотя скрипты их допускают.
- Клиент проверки стоит на хосте агента рядом с узлом, в том же дата-центре. Работу узла через
  провайдера с блокировками не проверял. Выбор Salamander опирается на стенд части 2, а смысл порта
  8443 подтверждается только реальной сетью; здесь проверено, что оба работают и включены.
- Прогон сбоев с разбором агентом был на двух транспортах, до Salamander и второго Reality. Сбой
  файрвола на 8443 проверен на текущем коде шагом и `verdict.sh`, без модели, остальные сбои не
  повторял. Интерактивный запуск на чистом сервере тоже был до этих правок.
- Захват настоящей модели не проверялся: она отказывается, поэтому запреты проверены подставной.
- Цена WebSearch у DeepSeek отдельно не замерялась. В поставке WebSearch и WebFetch запрещены.
- Версии закреплены: Claude Code 2.1.316, Xray v26.10.31, Hysteria v2.13.0. На других версиях Claude
  Code настройки выше не проверял.
- Баланс DeepSeek показывает два знака, поэтому расход мелких прогонов на нём не виден.
